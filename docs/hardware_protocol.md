# Железо реактора: цепочка, протокол, защита

```
датчики + 3 реле ──► Arduino ──USB Serial──► Raspberry Pi ──сеть (кабель / Wi-Fi)──► ноутбук
                     (главная защита)        (вторая защита,          (дашборд «Реактор»,
                                              журнал SQLite)            ИИ-агент — только чтение)
```

| Уровень | Код | Что делает |
|---|---|---|
| Arduino | `firmware/bioreactor/bioreactor.ino` | читает датчики, переключает реле, **главная защита** |
| Arduino (настройка) | `firmware/sensor_test/sensor_test.ino` | печатает сырые значения всех датчиков, реле всегда выкл |
| Raspberry Pi | `raspberry/bioreactor_pi/` | мост USB ↔ сеть, **вторая защита**, журнал SQLite, HTTP API |
| Ноутбук | `src/hardware/`, страница «Реактор» | показания, графики, кнопки (только человек), агент читает копию |
| Симулятор | `raspberry/bioreactor_pi/virtual_arduino.py` | виртуальная Arduino с теми же правилами; ноутбук запускает с ней настоящий код Pi |

## 1. Arduino ↔ Raspberry Pi (USB Serial)

115200 бод, одна JSON-строка на сообщение, конец строки `\n`, UTF-8 (на деле ASCII), не длиннее 512 байт.

### Arduino → Pi

**Состояние — раз в 1 с:**
```json
{"type":"state","seq":12,"uptime_ms":24000,"temp_c":36.8,"rh_pct":88.0,"gas_in":512,"gas_out":95,"p_kpa":1.42,
 "relays":{"heat":1,"cool":0,"pump":0},
 "alarms":{"leak":0,"overheat":0,"watchdog":0,"temp_sensor":0,"warmup":0}}
```

| Поле | Единица | Датчик (пока плейсхолдер) | Примечание |
|---|---|---|---|
| `temp_c` | °C | DS18B20 (влагозащищённый щуп) | `null` = датчик не отвечает → подогрев выключен |
| `rh_pct` | % | DHT22 | `null` = нет датчика |
| `gas_in` | сырой АЦП 0–1023 | MQ-4 внутри | **индикатор газа, не «% метана»**: MQ не измеряет концентрацию CH₄ без калибровки |
| `gas_out` | сырой АЦП 0–1023 | MQ-4 / MQ-2 снаружи | датчик утечки, порог `GAS_OUT_LEAK` |
| `p_kpa` | кПа (избыточное) | MPX5010DP (аналоговый) | «сколько газа скопилось», порог откачки 2,0 кПа |

Значение вне физического диапазона Pi считает отказом датчика (`null`).

**Ответ на каждую команду:**
```json
{"type":"ack","id":17,"ok":1,"relays":{"heat":1,"cool":0,"pump":0}}
{"type":"ack","id":17,"ok":0,"reason":"interlock","relays":{"heat":0,"cool":1,"pump":0}}
```
Причины отказа: `interlock`, `leak_lock`, `overheat`, `temp_sensor`, `warmup`, `still_leaking`, `unknown_relay`, `bad_cmd`.

**Сработала защита Arduino:** `{"type":"event","code":"leak_heat_off"}` (также `leak`, `overheat_heat_off`,
`temp_sensor_heat_off`, `watchdog_all_off`, `pump_empty_off`).
**После включения / сброса:** `{"type":"boot","fw":"0.1","proto":1}`. Все реле выключены.

### Pi → Arduino
```json
{"cmd":"relay","name":"heat","state":1,"id":17}
{"cmd":"ping","id":18}
{"cmd":"all_off","id":19}
{"cmd":"reset","id":20}
```
`id` — номер команды, Arduino возвращает его в `ack`. `reset` снимает блокировку после утечки, но только если газа
снаружи уже нет (иначе `still_leaking`).

## 2. Защита — три уровня

Правило для всех уровней: **автоматика только ВЫКЛЮЧАЕТ**. Включает только человек: кнопка на ноутбуке и подтверждение.

| Событие | Arduino (главная) | Raspberry Pi (вторая) | Ноутбук |
|---|---|---|---|
| Старт | все реле выкл до `Serial.begin` | после переподключения USB Arduino перезагружается → всё выкл | — |
| Утечка снаружи ≥ порога | подогрев выкл + блок до `reset` | тоже выключает подогрев, ставит блок, тревога в журнал; сброс только человеком и только когда газ ушёл | тревога на весь экран, кнопка подогрева заблокирована, кнопка «Сбросить тревогу» |
| Перегрев ≥ 45 °C | подогрев выкл, снова можно ниже 43 °C | то же + запись в журнал | тревога, кнопка заблокирована |
| Нет температуры | подогрев выкл и запрещён | то же | «датчик не отвечает» |
| Подогрев + охлаждение | второй отказ `interlock` | отказ до отправки на Arduino | кнопка неактивна с подсказкой |
| Нет команд 10 с | **все реле выкл** | шлёт `ping` каждые 2 с | — |
| Нет данных от Arduino 5 с | — | «нет связи с Arduino», все команды отклоняются | «НЕТ СВЯЗИ С ARDUINO», кнопки неактивны |
| USB выдернут | (реле выкл по 10 с) | переподключение каждые 3 с | то же |
| Ноутбук молчит > 15 с | — | шлёт `all_off`, тревога `laptop_lost` | — |
| Нет связи ноутбук ↔ Pi 5 с | — | (через 15 с — `all_off`) | «НЕТ СВЯЗИ С RASPBERRY PI», кнопки неактивны |
| Давление ≥ 3 кПа | (насос выкл при ≤ 0,1 кПа) | тревога в журнал | «опасно — откачайте газ» |
| Прогрев MQ (60 с после включения) | подогрев запрещён, утечка ещё не проверяется | `warmup` | предупреждение |

## 3. Raspberry Pi ↔ ноутбук (HTTP, порт 8780)

| Запрос | Ответ |
|---|---|
| `GET /health` | `{"ok":true,"version":"0.1","simulated":false,"arduino_ok":true,"port":"/dev/ttyACM0","firmware":"0.1"}` |
| `GET /state` | показания + уровни (норма/внимание/опасно), реле (вкл, сколько работает, почему заблокировано), тревоги, связи |
| `GET /history?window=600` / `3600` | точки для графиков за 10 мин / 1 ч (не больше 400) |
| `GET /journal?limit=50` | журнал команд и тревог |
| `GET /events` | поток Server-Sent Events: `event: state` раз в секунду |
| `POST /relay` | `{"name":"heat","state":1,"who":"operator","confirm":true}` → `{"ok":true}` или `{"ok":false,"reason":"interlock"}`; без `confirm` — 428 |
| `POST /reset` | `{"who":"operator","confirm":true}` — сброс тревоги утечки человеком |
| `POST /simulate` | только с `--simulate`: `{"what":"leak"\|"usb"\|"arduino_silent"\|"temp_sensor","on":true}` |

Любой запрос ноутбука = «ноутбук на связи» (дашборд опрашивает `/state` раз в секунду). Если в конфиге задан
`http.token`, нужен заголовок `X-Bioreactor-Token`.

Ноутбук (`data/config/reactor_hardware.json`): `"mode": "pi"`, `"pi_url": "http://192.168.50.2:8780"`. Страница
«Реактор» → кнопка «Проверить связь». Источник на странице всегда виден: **«СИМУЛЯТОР»** или
**«RASPBERRY PI → ARDUINO (192.168.50.2:8780)»**.

## 4. Журнал (SQLite на Pi, `/var/lib/bioreactor-pi/journal.sqlite3`)

- `events`: время (UTC), вид (`command`, `alarm`, `safety`, `link`, `system`), что, **кто** (`operator` — человек
  кнопкой, `pi_safety`, `arduino_safety`, `system`), результат, источник (`arduino /dev/ttyACM0` или `virtual`).
- `readings`: показания и состояние реле раз в 5 с (`reading_log_every_s`).

Записи только добавляются. Запись симулятора всегда помечена `virtual`.

## 5. ИИ-агент

Инструмент `get_reactor_status` (`src/agent_v10/tools/reactor.py`) получает **копию** состояния (`src/hardware/live.py`).
Вопросы «что сейчас в реакторе», «показания датчиков», «пора откачивать?», «есть утечка?» распознаёт Python. Ответ
пишет Python: числа датчиков, источник (симулятор / Pi), советы по правилам. Например: «температура 31 °C ниже режима
37 °C — рекомендую включить подогрев». На «включи подогрев» агент отвечает отказом: реле включает только человек.
У агента нет ни одного пути к командам: тест `test_agent_code_has_no_path_to_relays`.

## 6. Что уточнить, когда будет железо

- модели датчиков и пины (начало `bioreactor.ino` и `sensor_test.ino`, должны совпадать);
- порог утечки `GAS_OUT_LEAK`: снять скетчем `sensor_test` в чистом воздухе и у газа зажигалки (не поджигая);
- нулевую точку давления `PRESSURE_OFFSET`, когда бочка открыта;
- реле с управлением LOW или HIGH (`RELAY_ACTIVE_LOW`);
- пороги в `/etc/bioreactor-pi/config.json` на Pi должны совпадать с константами скетча.
