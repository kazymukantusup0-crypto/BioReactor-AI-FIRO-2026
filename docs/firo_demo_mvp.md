# FIRO Demo MVP

Из каталога `BioReactor_AI`:

```powershell
python -X utf8 main.py dashboard --firo-demo --port 8770
```

Команда открывает `http://127.0.0.1:8770/dashboard/#/demo`. Для запуска без автоматического открытия браузера добавьте `--no-browser`. Остановка запуска из консоли — Ctrl+C. Если порт занят уже работающим Demo, откройте его адрес.

Режим использует отдельную базу `data/runtime/firo_demo.sqlite3` и отключённый рыночный планировщик. Обычный запуск без `--firo-demo` сохраняет прежнюю конфигурацию; новые демонстрационные операции требуют явного флага.

1. Нажмите **Запустить A**, **B** или **C**. Результат сразу формируют существующие научные Python-инструменты и проверенные источники.
2. Просмотрите исходные данные, проверенный ответ, происхождение чисел и недостающие параметры. Демонстрационные входы не являются данными подключённых датчиков.
3. При желании нажмите **Получить пояснение Qwen3 4B**. Также можно заранее включить переключатель пояснений. Выполняется максимум один запрос к `qwen3:4b-q4_K_M`; вычислений модели не доверяют.
4. При нехватке ресурсов, недоступной модели или отклонённом пояснении основной ответ остаётся доступным. Неудачный черновик не выдаётся за результат Qwen, прошедший проверку.
5. Последний результат восстанавливается после обновления страницы. Сервер сохраняет результат и диагностику в SQLite, браузер — только его идентификатор.

Сценарии:

* A: заданные 0,6 кг VS и BMP 250 мл CH₄/г VS дают **150 л CH₄** как расчётный потенциал; выход за 30 дней не установлен.
* B: 142 л коровьего навоза и номинальные 200 л сосуда не задают массу, VS, BMP, рабочий объём или кинетику; прогноз не выдумывается.
* C: анаэробность, отсутствие потребности в свободном кислороде и разные пути метаногенеза, включая восстановление CO₂ водородом, объясняются по источникам.

Пояснение Qwen использует локальную Ollama `localhost:11434`, контекст 4096, batch 32, один одновременный запрос, 400 выходных токенов и timeout 45 секунд. Существующий QA-допуск RAM 6656 MiB и мониторинг RAM/commit/VRAM/GPU сохранены. После запроса выполняется адресная выгрузка модели с проверкой; занятая другим клиентом Ollama не вмешивается в основной ответ. Отмена доступна во время пояснения; поздний текст не заменяет отменённый результат.

Разовая реальная проверка API через существующий QA-клиент:

```powershell
python -X utf8 evaluations/qwen4b_manual_chat.py --confirm-experimental --firo-demo-case methane
```

Другие варианты: `incomplete`, `oxygen`. Это опциональные реальные LLM-запуски с допуском, не unit-тесты.

Браузерные проверки:

```powershell
cd frontend
node tests/firo-demo-mvp-browser.mjs
node tests/firo-demo-mvp-browser.mjs --with-qwen
```

Для ретеста только пояснения B добавьте `--live-case=B`. Артефакты и снимки — `reports/firo_demo_mvp/`. Базовый URL можно задать переменной `BIOREACTOR_DEMO_URL`.

Границы MVP: три заранее определённых сценария, без управления оборудованием и датчиков. Общий свободный Chat, прочие расчёты и независимый FIRO acceptance не получают статус READY из этой демонстрации.

## Литературная оценка при неполных данных

Сценарий B теперь показывает условный BMP-ориентир для 142 л навозной жижи и отдельно — отсутствие обоснованного 30-дневного прогноза. Параметры берутся из одного рассмотренного исследования; измеренные параметры пользователя не заменяются литературными. Форма сырья остаётся допущением до подтверждения. Источники и режим оценки видны в интерфейсе и сохраняются в истории.

Тот же движок доступен через `POST /api/advisor/estimate`:

```json
{
  "components": [{"id":"c1","material":"cattle_manure","quantity":142,"unit":"L"}],
  "estimation_mode":"LITERATURE_ESTIMATE",
  "allow_conditional_profiles":true,
  "allow_literature_density":true,
  "target_days":30,
  "reactor_total_volume_l":200
}
```

`MEASURED` отключает подстановку литературных параметров. Это расчёт по измеренным входам, а не измеренная выработка. `LITERATURE_ESTIMATE` явно разрешает сценарий по совместимому опубликованному образцу; исходный строгий запрет автоматической конверсии литров сохраняется вне этого режима. `INSUFFICIENT_EVIDENCE` обозначает отсутствие обоснованного численного результата; полный потенциал и выход за срок получают собственные статусы.

Для выхода за срок нужны применимые данные накопления газа или подтверждённая модель. Поддерживается явный пользовательский first-order fit: `kinetic_evidence` с `rate_per_day`, `lag_days`, `temperature_c`, `reference` и `applicable_to_batch=true`, измеренными свойствами партии и совпадающей `process_temperature_c`. Числовые коэффициенты по умолчанию не подставляются; программа не подтверждает качество заявленного пользователем fit. Лабораторная длительность BMP не становится временем работы установки.

Реальный ограниченный ретест существующим QA-клиентом:

```powershell
python -X utf8 evaluations/qwen4b_manual_chat.py --confirm-experimental --limited-chat --case C
```

Он использует настоящий Qwen3 4B и фактический Chat jobs endpoint через FastAPI TestClient. Ресурсный допуск, мониторинг, ограничения четырёх вызовов и времени, адресная выгрузка сохранены. Не запускайте одновременно другие запросы к Ollama. Новый результат, источники, реальные черновики, ограничения и телеметрия: `reports/literature_methane_estimates_20261112.md`.
