## Три реальных диалога (живой агент, 16.11.2026)

### 1. «Хватит ли газа на подогрев?»
**Вопрос:** «У меня 150 литров коровьего навоза, бочка 200 литров не утеплена, на улице −10. Сколько будет газа и хватит ли его на подогрев?»

Шаги агента:
1. Факты (Python): навоз КРС 150 л, реактор 200 л, без утепления, −10 °C.
2. Шаг 1 (2.5 с, промпт 1339 токенов): модель вызывает `estimate_methane` и `estimate_heating_energy`.
3. Python добавляет вывод `gas_vs_heating`.
4. Шаг 2: модель пишет ответ → проверка чисел: ок. Всего 3.9 с.

Карточки: метан 2.2–3.9 м³; биогаз 3.7–7.1 м³; энергия газа 22–39 кВт·ч; подогрев 266–549 кВт·ч; **хватит газа на подогрев? — нет; газ покрывает 3.4–13 %**.
**Ответ:** «У вас получится около 3,7 м³ биогаза, но его недостаточно для подогрева бочки. Нужно дополнительно подогревать биогазом или электричеством.»
**Вопрос агента:** «Навоз жидкий или твёрдый/с подстилкой?»

### 2. Память диалога: «а если добавить…»
**Вопрос 1:** «У меня 200 л жидкого навоза КРС. Сколько газа?» → модель вызвала `estimate_methane` → метан 2.9–5.2 м³, биогаз 4.9–9.5 м³ (2.8 с).
**Вопрос 2:** «А если добавить 30 кг пищевых отходов?»
Шаги: Python добавил компонент к запомненной партии → модель вызвала `compare_scenarios` → проверка чисел: ок (5.0 с).
Карточки: метан смеси 4.5–9.1 м³; прибавка метана 1.5–3.8 м³; чистый баланс смеси −683 … −268 кВт·ч.
**Ответ:** «Добавление 30 кг пищевых отходов увеличит объём газа с 4,9–9,5 м³ до 7,3–16 м³…»

### 3. Казахский язык
**Вопрос:** «Сиыр көңі 200 литр, қанша газ болады?»
Шаги: язык kk → модель вызвала `estimate_methane` → проверка чисел: ок (2.9 с).

## Решения, принятые самостоятельно

1. **num_ctx = 8192.** Скорость как у 4096 (53 и 55 ток/с), +0.6 ГБ видеопамяти, всё на GPU. При переполнении 4096 Ollama молча отрезает начало промпта, то есть правила агента.
2. **Демо-реактор.** Если загрузка не больше 160 л — берётся бочка 200 л; если больше — реактор считается под загрузку. Утепление по умолчанию сменилось с «базового» на «нет».
3. **Вывод «хватит ли газа» считает Python** (`gas_vs_heating`). Модель в живом диалоге сказала «хватит» при покрытии 3–13 %; проверка чисел это не ловит.
4. **Физические параметры берутся только из слов пользователя.** Модель подставила `days: 20`, которых никто не называл. Теперь такие значения игнорируются, а недостающие берутся из демо-реактора и пишутся в допущения.
5. **Старый чат не удалён** — он доступен на `#/chat-v9`.
6. **Отдельные стили `ac-*`** и отдельная кнопка «Режим жюри» вместо правки общего `styles.css` и переключателя «Простой/Научный».
7. **`start.bat` пересобирает интерфейс**, если исходники новее сборки: `frontend/dist` не хранится в git.
8. **Карточки хранятся вместе с ответом в истории**, но модели отправляются только роль и текст.

## Что не получилось / ограничения

- **Проверка чисел проверяет происхождение числа, а не смысл.** Для «хватит ли газа» это закрыто выводом Python. Для других выводов модель всё ещё может назвать число не тем словом. Источник правды — карточки.
- **Широкие диапазоны у смесей** («до 7,3–16 м³»). Это честное сложение худшего с худшим и лучшего с лучшим, но выглядит размыто.
- **Старый тест v9** `test_reactor_capacity_dashboard.py::test_chat_job_endpoint_enforces_470_l...` один раз упал в полном прогоне. Отдельно он прошёл 3/3, следующий полный прогон — зелёный. Вероятно, нестабильность по времени, к v10 не относится.
- **cmd-особенность:** из командной строки `call start.bat` по короткому имени не находится (имя совпадает с командой `start`). По двойному клику и по полному пути работает. Переименовывать не стал — файл упомянут в инструкциях.
- **Ускорение первого токена** (5.5 → 1.6 с) связано не с num_ctx. Вероятные причины — ограничение длины ответа и не разогретая видеокарта. На горячем ноутбуке может быть медленнее.
