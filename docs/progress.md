**08:27 · Демо-реактор (8524ea7).** Новый файл `data/config/demo_reactor.json`: бочка 200 л, рабочий объём 160 л,
без утепления, жидкий навоз КРС, +5 °C, 37 °C, 30 дней. Загружается функцией `config.demo_reactor()`.
- Решение: если объём реактора не назван, но загрузка ≤ 160 л — берём бочку 200 л; если загрузка больше
  (например, 300 л) — реактор считается под загрузку (загрузка / 0.8), иначе 300 л «не влезли бы» в 200 л.
- Решение: умолчание утепления сменилось с «базовое» на «нет» (как у демо-бочки). Из-за этого оценки
  подогрева без указания утепления стали заметно больше — это честно для неутеплённой бочки.
- Тест с ручным расчётом: 160 кг × 4.0 × 32 / 3600 = 5.69 кВт·ч; A = 1.894 м²; UA·ΔT·t = 261.8 … 551.0 кВт·ч.

**08:29 · Контекст 4096 / 8192.** В `scripts/benchmark_ollama.py` добавлены `--num-ctx` и замер «длинного промпта»
(~3900 токенов, новый текст без кэша Ollama). Итог (`docs/benchmark.md`): qwen3:8b — 4096: 5.59 ГБ, 55 ток/с,
длинный промпт 2.27 с; 8192: 6.19 ГБ, 53 ток/с, 2.30 с; обе 100% на GPU.
- Решение: `num_ctx` = 8192 в `data/config/llm_selection.json`. Почему: скорость та же, +0.6 ГБ VRAM (запас 1.8 ГБ),
  а при переполнении 4096 Ollama молча отрезает начало промпта — то есть системные правила агента.
  Сейчас самый большой промпт ~2000 токенов, но длинный диалог с историей мог бы упереться в 4096.
- Старый QA-профиль qwen3:4b (`evaluations/`, `tests/test_qwen4b_*`) остаётся на 4096 — это отдельный профиль, не трогаю.

**08:45 · Найдена и исправлена смысловая ошибка (e25921f).** В живом диалоге «150 л навоза, бочка не утеплена,
−10 °C, хватит ли газа на подогрев?» модель ответила «хватит», хотя газ 22–39 кВт·ч, а подогрев 266–549 кВт·ч.
Проверка чисел это не ловит (все числа настоящие).
- Решение: новый производный результат `gas_vs_heating` (Python): тепло газа × КПД котла 0.85–0.90 / потребность
  → покрытие 3.4–13 %, вердикт «нет». Модель получает готовый вывод, интерфейс — карточку «Хватит газа? — нет».
  После исправления модель отвечает «газа недостаточно для подогрева».
- Там же модель сама подставила `days: 20`, которых пользователь не говорил. Решение: объём, утепление,
  температуры и срок берутся только из фактов, извлечённых Python из слов пользователя (или из панели);
  иначе — демо-значение и явное допущение.
- В eval добавлен 11-й диалог про «хватит ли газа». Итог: 14/14 инструмент, 14/14 числа, 14/14 язык,
