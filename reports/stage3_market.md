Проверка: 28.10.2026. Продолжен существующий проект. BMP-модели не переобучались;
все 67 прежних файлов данных, моделей и отчётов сохранены по SHA-256.
Предыдущие CLI-команды и ручной `calculate_profitability` остаются доступны.

Итог: **73 теста прошли**, выполнено **26 настоящих HTTP-запросов** к локальному
Uvicorn-серверу. Новые рыночные инструменты проверены в фактическом диалоге с Ollama.
В рабочей базе два реальных исторических наблюдения и **ноль тестовых цен**.

## Реализовано и запуск

FastAPI + SQLite, пять категорий рынка, адаптеры, ручной ввод, CSV, ежедневное
обновление, история, аналитика и четыре новых инструмента агента.

Из родительской рабочей папки:

```powershell
python -m pip install -r BioReactor_AI/requirements-market.txt
python BioReactor_AI/main.py market serve
```

Сервер слушает только `127.0.0.1:8765`; `/docs` содержит схему API. Он работает,
пока открыт процесс в терминале; `Ctrl+C` завершает его. Фоновый планировщик работает
внутри процесса сервера, а не как служба Windows и не во время выключения ноутбука.
Рабочая база: `BioReactor_AI/data/market/market.sqlite3`.

Проверка без браузера:

```powershell
Invoke-RestMethod http://127.0.0.1:8765/health
Invoke-RestMethod 'http://127.0.0.1:8765/prices/current?region=KZ-Almaty'
Invoke-RestMethod 'http://127.0.0.1:8765/prices/history?commodity=electricity&region=KZ-Almaty'
Invoke-RestMethod 'http://127.0.0.1:8765/analytics/price-change?commodity=electricity&region=KZ-Almaty'
python BioReactor_AI/main.py market status
python BioReactor_AI/main.py market update
python BioReactor_AI/main.py chat
```

`BIOREACTOR_MARKET_DB` задаёт другой SQLite-файл. `BIOREACTOR_MARKET_INTERVAL_SECONDS`
задаёт период в секундах (по умолчанию 86400, минимум 5). Планировщик запускает
первую попытку при старте. `BIOREACTOR_MARKET_SCHEDULER=0` отключает автоматические
обновления; ручной `/updates` остаётся доступен. Чтение сохранённых данных не требует
интернета. Агент использует тот же сервис и файл SQLite, поэтому HTTP-сервер не
обязателен для локального чтения агентом уже накопленных цен.

## HTTP API

| Метод и путь | Назначение |
| --- | --- |
| GET /health | База, интервал и состояние настройки планировщика |
| GET /catalog | Товары, категории и известные регионы |
| GET /sources | Настроенные источники и адаптеры |
| POST /sources | Добавить новый источник; существующий ID не перезаписывается |
| GET /prices/current | Последние известные наблюдения, отдельно по сопоставимым сериям |
| GET /prices/history | История товара/региона, start/end по датам действия |
| GET /analytics/price-change | Абсолютные и процентные изменения внутри каждой серии |
| POST /prices | Ручной ввод одного наблюдения |
| POST /prices/import-csv | Атомарный импорт JSON-объекта с полем csv_text |
| GET /updates | Последние попытки обновлений и ошибки источников |
| POST /updates | Обновить все категории или одну через query category |
| POST /scenarios/compare | A/B/C/D, цены, недостающие данные, чувствительность и безубыточность |
| GET /scenarios | История экономических расчётов |
| GET /scenarios/{id} | Зафиксированные входы и результат отдельного расчёта |

`/prices/current` означает latest known: он не обещает, что каждая возвращённая
цена пригодна как текущая. Поля `age_days`, `is_stale`, `is_superseded`,
`publication_date_unknown`, `usable_as_current` обязательны для интерпретации.
Новая цена одной серии делает прежнюю заменённой даже в пределах окна свежести.
Будущая дата начала действия не делает цену действующей сегодня.

## Наблюдения и SQLite

Таблицы: sources, categories, commodities, regions, observations, updates,
scenarios и leases. Для observations и scenarios SQLite-триггеры запрещают UPDATE
и DELETE. Изменение цены записывается новой строкой. Дубликат определяется
производителем/товаром/регионом/типом/условиями/датами и нормированной ценой;
новая дата получения или другой текст примечания не создают фиктивный рост истории.
Смена даты действия создаёт новое наблюдение, даже если цена сохранилась.

Хранятся оригинальные и нормированные значение/единица, валюта, дата публикации,
дата действия, срок при наличии, дата получения UTC, страна, регион, источник,
тип цены, класс потребителя, основание НДС, условия объёма газа, доказательство
и статус достоверности. Неизвестная дата публикации сохраняется null, не заменяется
датой действия или получения. Каждая попытка получения отдельно записывается в updates.
Границы дня для основного рынка считаются по календарю Asia/Qyzylorda, независимо
от часового пояса хоста; timestamps получения и выполнения хранятся с UTC-offset.

Нормировка цены выполняется через Decimal: цена за тонну /1000 = цена за кг;
цена за МВт·ч /1000 = цена за кВт·ч; цена за 1000 м³ /1000 = цена за м³.
Литры не переводятся в массу без плотности. Денежные сценарии используют float
с проверкой конечности; это расчётные оценки, не бухгалтерское округление платежей.
Нет автоматических валютных курсов, конверсии давления/температуры газа или замены
товара другим. Новые страны задаются через country/region/currency, без скрытого
применения казахстанского тарифа к иному рынку.

Свежесть по умолчанию — 30 дней, консервативно от наиболее ранней известной даты
публикации/действия, а не от последнего скачивания. Неизвестная публикация,
неподтверждённая достоверность, неподходящая категория или тестовая запись не могут
молча стать актуальной ценой. Явный price_id тоже проверяется, а не обходит фильтры.

работающего Python-скрейпера. Даты публикации неизвестны; обе записи не выдаются
как пригодные текущие цены. Источники: [июньское объявление](https://www.esalmaty.kz/ru/i4160)
и [страница тарифов](https://www.esalmaty.kz/ru/business-tariffs).

Их изменение по датам начала действия — около 8,17%; две точки не являются
полной историей рынка и не доказывают отсутствие промежуточных тарифов. Нельзя
считать Алматы представителем всего Казахстана.

## Ручной импорт и расширение

Заголовок CSV находится в `examples/market_prices_template.csv`. Значения цен в
нём намеренно отсутствуют. Заполните их из реального прайса/договора с датами,
единицами, регионом, условиями и ссылкой либо идентификатором документа.

```powershell
python BioReactor_AI/main.py market import-csv --input C:/path/verified_prices.csv
```

Источник должен существовать. Для готовых ручных источников ID:
qazaqgaz_aimaq, organic_verified_manual, mineral_verified_manual,
feedstock_verified_manual. Наблюдения ручного API/CSV с заявленным verified_official
переводятся в verified_manual: ручной ввод не считается автоматической проверкой.
Unverified хранится в истории, но не используется для рекомендации.

Для автоматического CSV добавьте `/sources` с adapter=csv, URL публичного HTTPS CSV
и полным форматом PriceInput. Без config.reviewed_schema=true результат остаётся
unverified. Эта настройка означает ручное принятие схемы администратором, а не
доказательство достоверности от программы. Специальный официальный HTML-адаптер
привязан к проверенному URL Энергосбыта; произвольный сайт нельзя выдать за него.
При изменении товара/схемы добавляйте отдельный адаптер и тест его парсера.

Для демонстраций нужны одновременно reliability=test и is_test=true. Такие цены
не попадают в обычный current/history и могут участвовать только в явно заданном
allow_test_prices=true сценарии, который помечается условным. В рабочей базе
тестовых цен нет. Наборы для тестирования HTTP находятся в отдельной временной БД.

## Экономика A/B/C/D

Запрос заполняется по `examples/market_scenario_template.json`: неизвестные величины
оставлены null. Регион и профиль тарифа в шаблоне — пример, их нужно проверить для
своей установки. Без параметров возвращаются причины по каждому варианту, а не
придуманный результат. Один ценовой ряд может иметь несколько поставщиков: тогда
выберите price_ids явно. Проверяются товар, регион, валюта, НДС, класс потребителя,
тип предложения, даты, достоверность и газовые условия.

| Вариант | Монетизируемая величина и ограничения |
| --- | --- |
| A | Масса × закупочная/оптовая цена сырья − хранение и перевозка при продаже |
| B | Экономия собственного потребления электричества из восстановленного CH4; выработка ограничена заданным спросом, излишек не оценивается как продажа в сеть |
| C | Продажа только сырого биогаза либо биометана по цене именно этого товара; нужны явные техническое/юридическое подтверждения и документ-основание |
| D | Продажа дигестата или экономия его прямого использования; нужны масса продукта, качество, допустимость рынка и при использовании подтверждение эквивалентности |

Потенциал CH4 = BMP × масса VS /1000 в м³. Реально извлекаемая доля задаётся
пользователем, не угадывается. Для B нужны энергетическая характеристика метана
при тех же условиях, электрический КПД и спрос; расчёт теплового CHP-кредита
в этой версии не реализован. Для сырого газа C объём = извлечённый CH4 / доля CH4.
Для биометана учитываются потери апгрейдинга и чистота. Природный газ хранится
отдельно и не служит ценой продажи ни одного из этих продуктов.

Из переработки вычитаются подготовка, нагрев, обслуживание, хранение, транспорт,
обращение с дигестатом, потреблённая энергия и соответствующая очистка/апгрейдинг.
Все затраты партии задаются явно, включая реальные нули. Operating_cost не должен
уже включать отдельно перечисленные энергию/нагрев/транспорт: такие пользовательские
дубли программа из свободного описания не определяет. Спрос электроэнергии задаётся
без собственных энергозатрат реактора, которые списываются отдельно.

B, C и D — самостоятельные альтернативы: газ, электроэнергия и дигестат не получают
одновременно одну и ту же выручку. D не добавляет газовый доход. Комбинированная
продажа газа и дигестата требует отдельного сценария с явным распределением и здесь
не рассчитывается. Минеральная цена не заменяет цену дигестата; перевод по N/P/K не
выполняется без отдельной модели качества и эквивалентности.

Финансовый ledger C сверяется настоящим вызовом прежнего calculate_profitability.
Для этого из выручки C вычисляется эквивалентная оценка на м³ извлечённого CH4;
она помечена derived_ch4_valuation_not_market_quote и не выдаётся за котировку
природного газа или товарного метана. Итоговая рекомендация возможна лишь когда
все варианты рассчитаны или явно исключены подтверждёнными ограничениями.
Неполное сравнение никогда не объявляет A выгоднее только из-за отсутствия B/C/D.

Чувствительность — изменение одной цены на ±20% при прочих фиксированных входах.
Учитываются и затраты электричества; эффект тарифа для B зависит от разницы
собственного замещения и энергопотребления реактора. Точка безубыточности дана как
цена, при которой вариант сравняется с чистым результатом A. При неположительном
объёме/марже конечная положительная точка не выдумывается. Это не прогноз будущих цен.

## Интеграция агента и фактическая проверка

Добавлены get_market_prices, get_price_history, compare_market_scenarios,
explain_market_recommendation. Экономический вопрос автоматически добавляет
рыночные инструменты после проверки сырья и BMP. Точные физические и финансовые
параметры передаются как market_scenario в JSON-контексте; market_region можно
задать отдельно. Упоминание Алматы распознаётся как пример конкретного региона,
но произвольные регионы в прозе не угадываются.

```powershell
python BioReactor_AI/main.py chat --message "У меня 20 кг пищевых отходов в Алматы. Что выгоднее: продать или переработать в биогаз?" --json
python BioReactor_AI/main.py tool get_market_prices --input C:/path/market_context.json
```

Для market_context.json достаточно `{"market_region":"KZ-Almaty"}`.
Для истории добавьте market_commodity и при необходимости market_start/market_end.
Для расчёта вложите заполненный запрос под ключ market_scenario. Смена сырья
сбрасывает параметры партии. У пользователя остаётся возможность прямого вызова
старого ручного calculate_profitability с прежними полями.

В реальном запросе через локальную Ollama новый план успешно вызвал рыночные
инструменты. Для 20 кг food_waste модель Hafner отказалась от BMP, а сравнение
запросило отсутствующие физические, финансовые и документальные основания.
Числовая прибыль для этой партии не выдумана.

## Проверки и ограничения

Полная воспроизводимая проверка:

```powershell
python BioReactor_AI/verify_stage3.py
```

Скрипт запускает настоящий Uvicorn на свободном loopback-порту, выполняет HTTP-запросы
и останавливает проверочный сервер. Он не оставляет его фоном: для работы запустите
market serve отдельно. TEST-записи находятся только во временной базе. Проверены
нормировка, дубликаты и запрет перезаписи, ошибка сети/источника, устаревание,
замещение новой ценой, mutex категорий, остановка scheduler, CSV, реальные денежные
результаты на явно тестовых входах, отсутствие цен/параметров, несовместимые товары,
единицы/регионы/валюты/НДС и агент. Старые научные тесты продолжают проходить.

HTTPX TestClient сообщает deprecation warning установленной версии Starlette;
это не ошибка тестов и не результат настоящего TCP-теста. Чистая установка зависимостей
на другом Windows-ноутбуке отдельно не проверялась. В текущей песочнице загрузка
CatBoost и внешняя сеть требуют разрешённого запуска вне песочницы.

Система пока не имеет подтверждённого автоматического внешнего потока цен. Для
полезной актуальной рекомендации нужно настроить доверенную TLS-цепочку/разрешённый
источник и импортировать региональные предложения на сырьё, биогаз и дигестат.
Подтверждения качества и правовой допустимости задаются пользователем; это не
юридическая экспертиза. Измерения эффективности и качество продукта не прогнозируются
из рыночных цен. Остаются ограничения BMP одного исследования и отсутствие
независимой проверки улучшения этапа 1.5. Прогноз будущих цен не обучался.
